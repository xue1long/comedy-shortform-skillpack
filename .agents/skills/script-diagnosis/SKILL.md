# 短剧诊断

## 目标
找出最影响笑点兑现与拍摄的具体断点，并给出可执行的优先修订点。

## 输入
原稿、用户要求保留的内容、目标时长、演员／场景／道具限制，以及用户是否明确授权改稿。缺失时不要臆测；尤其区分“诊断”与“改稿”授权。

## 适用条件
已有剧本的诊断；不从空白创意直接写完整剧本。用户从一句创意要成稿时使用 `comedy-shortform-writer`。

## 步骤
1. 复述原稿承诺的核心笑点、人物关系和必须保留项，避免以诊断为由悄悄替换。
2. 逐项检查结构因果、人物行为、setup/payoff、时长估算、可拍性和输出清晰度；引用具体台词、动作或段落作为证据。区分用户给出的目标时长与明确的成片硬上限。
3. 按对核心笑点和交付的损害排序，只列可在文本中定位的问题；区分明确失败与可能风险。
4. 只有用户明确授权改稿时，才按目标做定向重写；完成后复核保留项、估算时长和拍摄限制。精简时优先删重复解释、合并同功能节拍、压缩冗长对白；补充时只沿原喜剧规则增加有效变化，不填充时长。

## 判断与停止
若必要修改必须触及保留项，先向用户说明冲突并询问取舍。初稿超出或短于目标时长本身不判失败：给出具体段落、估算可省／可增加的时间和优先顺序。仅当用户明确要求成片硬上限而修订稿仍超限、违反制作限制或核心笑点无法兑现时，才标「待修改稿」。没有明确改稿授权时停留在诊断和建议。

## 输出
依次给出核心承诺与保留项、目标及估算时长、问题位置、影响、优先级、文本证据、精简／补充方案；仅在用户明确授权时附改稿及复核结果。

## 边界与失败
不把“我觉得不好笑”当作唯一证据；不擅自重写受保护的核心笑点；不把建议冒充已验证的观众反应或时长测试。

## 示例
若 payoff 依赖一名未在预算内出现的演员，指出该动作所在节拍与演员限制冲突，并建议用现有演员和道具改写该动作；若替代方案改变核心笑点，先征求授权。

## 相关技能
完整创作使用 `comedy-shortform-writer`；局部机制可用 `comedy-engine`。本 Skill 可独立调用。
