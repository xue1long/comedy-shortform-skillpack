# 喜剧短剧编剧

## 目标
产出遵守明确创意、目标时长、原稿保留项与制作限制的可拍短剧本。默认以 60 秒为规划参考。

## 输入
识别创意或原稿、人物、场景、基调、时长与制作限制。原稿默认保留人物关系、核心笑点和重要情节节点。将明确要求与推测分开；不能把猜测写成用户给定的事实。

## 适用条件
适用于完整创作或改稿。用户只问笑点机制、Sketch 结构、双主角关系或剧本诊断时，使用对应独立 Skill；当前 Skill 不依赖其他 Skill 自动触发。

## 步骤
1. 用简短清单复述核心前提、明确制作限制、原稿保留项和必要假设。缺少核心创意、关键事实矛盾或保留要求互相冲突时，一次最多问 3 个决定性问题，然后停下。
2. 将时长当作目标和估算值，不当作初稿的硬门槛。用户给出时长时按该时长规划；未给出时以 60 秒为参考。初稿超出或短于目标都可继续完成，不能因此拒绝写作、擅自改目标或直接判失败。
3. 判断人物的眼前目标、阻碍、冲突和喜剧前提是否成立。提炼角色遇到压力时反复采用的错误策略，以及该策略如何造成可见后果；信息不足以支撑核心行动时先提问，不用随机事件替代因果。
4. 判断喜剧前提能否转为演员可见的行为。Sketch（按重复规则组织）与双主角（两人相互改变局面）分别判断，可以同时成立；不要强迫二选一，并简要说明选择理由。
5. 按目标时长安排 setup、变化和 payoff。时间码覆盖实际稿件全长，不强行截断在目标秒数；只在能强化现有机制且不挤掉 payoff 时使用升级或 callback。
6. 写清地点、演员、动作和对白。估算正常语速下的对白时长，另计动作、反应和停顿；并行动作与对白只计一次实际经过时间，静默也占用时间。时间码从 0 秒连续覆盖到结尾，不跳段、不重叠累计。
7. 检查创意与原稿保真、人物因果、笑点兑现、时长估算、可拍性和输出完整性。若初稿偏离目标，标出偏差和具体可改段落；未要求成片版时先交完整初稿及精简／补充选项。用户要求成片版、硬上限或明确要求改稿时，按下方修订顺序做定向修改。改动受保护的核心项前先征求确认。

## 判断与停止
关键输入缺失、要求冲突或用户尚未授权改变原稿核心项时，停在澄清问题，不输出 Beat Sheet 或完整剧本。初稿低于或超过目标时长，不构成单独的失败条件：如实标注估算时长、偏差和精简／补充方向。若用户要求成片版或明确的最长时长，则继续修订；修订后仍未满足该明确要求时，标注「待修改稿」并说明具体原因。

## 时长迭代

- **初稿偏长：**先删重复解释，再合并承担同一功能的节拍，再压缩冗长对白。保留前提建立、人物选择、有效升级和 payoff；必要的喜剧停顿不能只因占时而删。每项建议标出段落和预计可省时间，不直接把修改建议冒充成已修订稿。
- **初稿偏短：**若故事已完整，说明短于目标但无需填充；若用户希望接近目标，只增加一轮由同一喜剧规则推动的变化或反应，不加无关支线和解释。
- **用户要求成片版：**实际删改或补充后重排连续时间码，复核因果、保留项和制作限制。说明估算的成片时长；估算不是试读计时，也不声称精确到秒。

## 输出
完整创作或改稿通过澄清后，依次给出：
1. **创意或原稿摘要与保留项／假设**：区分用户明确内容与必要假设。
2. **喜剧形式与人物配置**：分别说明是否采用 Sketch 规则和双主角关系。
3. **时间码 Beat Sheet**：从 0 秒连续列至剧本结尾，列出 setup、变化、payoff 及累计时长；同时列出目标时长（若有）和初稿估算总时长。
4. **短剧本**：逐段写场景、可拍动作和对白。
5. **诊断和本轮修订点**：说明稿件状态（初稿／成片候选稿）、时长目标、估算总时长和偏差；若尚未改稿，列出具体精简／补充选项；若已改稿，说明删改取舍。只有明确交付要求仍未满足时才标「待修改稿」。

## 边界与失败
不把短剧本声称为特定视频模型可直接执行的提示词。若用户要求明确时长上限，而核心笑点无法在该上限或制作限制内保留，先说明冲突并询问取舍；不得静默替换原稿核心笑点。未澄清前不生成违反关键限制的成片版。

## 示例
输入：一人按闹钟，台灯误以为他起床。若目标为 60 秒，可先用 0–10 秒建立错误庆祝、10–45 秒安排两次变化、45–60 秒兑现规则；若初稿演出估算为 68 秒，标出可剪的重复反应或对白，保留 payoff。台灯的变化须由现有道具和一名演员可拍地表现。

## 底层能力路由

写作流程按阶段调用 `distillation/capability-map.md` 中映射的书籍 Pack router；每个 router 负责把任务转发到其晋升的独立 Skill。**不能只引用名称就声称调用**——每阶段必须实际加载对应 router 的 SKILL.md，按其中的路由表选一个 promoted skill，应用其方法后再回到本流程。

按工作流阶段调用：

| 工作流阶段 | 调用的 pack router | 用到的方法 | 期望产出 |
|---|---|---|---|
| 提炼喜剧规则 | `comic-toolbox` | Comic Premise + Law of Comic Opposites | 一句 falsifiable 的喜剧规则 |
| 设计人物 | `art-of-character` 或 `hidden-tools-comedy` | Character Desire / Comic Hero | 人物 want/need + 行为模式 |
| 搭建节拍 | `comedy-writers-companion` 或 `comedy-bible` | Comic Skeleton / Joke Structure / Rule of Three | 节拍顺序 + 升级序列 |
| 写对白 | `writing-dialogue` | Dialogue Misdirection + Compression | 可压缩的对白轮次 |
| 场景/镜头设计 | `screenplay` 或 `comedy-movie` | Scene Design / Genre Formula | 场景冲突和设置 |
| 双人攻防 | `comedy-writers-companion` (comic-duo) 或 `hidden-tools-comedy` (straight-wavy-line) | Duo Structure / Straight-Wavy | 双人攻防节拍 |
| 情景/长篇 | `sitcom` | Sitcom Arc | 三态节拍 (stability→instability→new stability) |
| 成品诊断 | `script-diagnosis` (项目适配) | 项目诊断方法 | 问题清单 + 修订点 |

每个 router 是独立的 pack 入口；promoted skill 可独立调用。当 router 缺失或不能覆盖当前需求时，使用项目适配 Skill：`comedy-engine`、`structure-sketch`、`structure-duo`、`script-diagnosis`（它们在此项目中是适配品，不是书籍蒸馏）。

## 相关技能
